# ChurchCare for Windows — Native Desktop Foundation

This is a traditional installed Windows desktop application built with **C# and WinUI 3 / Windows App SDK**. It is not a website, PWA, WebView wrapper, or browser-derived application.

## Current foundation

- Native Windows desktop shell with a left navigation rail.
- First-run church profile setup with a user-defined hierarchy (highest level first), starting level, and branch/unit name.
- Local SQLite database under `%LOCALAPPDATA%\\ChurchCare\\churchcare-windows.db`.
- Dashboard counts and church profile summary.
- Member creation and search.
- Church structure level listing and adding levels.
- Desktop About and local database location screens.
- GitHub Actions builds a self-contained x64 Windows publish folder, a conventional per-user setup installer, and a portable ZIP.
- Original ChurchCare launcher artwork is restored from the repository's supplied base64 asset during CI.

## Build locally

Requirements: Windows 10 version 1809 or later (Windows 11 recommended), .NET 8 SDK, and the Windows App SDK dependencies restored by NuGet.

Restore the PNG asset before building (PowerShell from the repository root):

```powershell
New-Item -ItemType Directory -Force rebuild/windows/ChurchCare.Windows/Assets | Out-Null
$raw = (Get-Content rebuild/assets/churchcare-original-icon.png.b64 -Raw) -replace '\\s',''
[IO.File]::WriteAllBytes('rebuild/windows/ChurchCare.Windows/Assets/ChurchCare.png', [Convert]::FromBase64String($raw))
dotnet publish rebuild/windows/ChurchCare.Windows/ChurchCare.Windows.csproj -c Release -r win-x64 --self-contained true -p:WindowsAppSDKSelfContained=true -o publish/ChurchCare
```

The installer is generated by Inno Setup using `rebuild/windows/installer/ChurchCare.iss`.

## Important product boundary

This is the first native desktop foundation, not yet feature-complete parity with Android. The current desktop database is local and offline-first. Authentication, shared backend, cross-device synchronization, simultaneous edits/conflict resolution, server-enforced church isolation and role permissions, full appointments/care/delegation workflows, and guided backup/restore remain future milestones. Do not use this foundation as a production multi-user/synchronized release yet.
